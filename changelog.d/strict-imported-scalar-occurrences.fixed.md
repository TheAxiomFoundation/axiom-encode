Credit an explicitly imported parameter in the complete-source-unit numeric-occurrence check. The check dropped the `#symbol` suffix of each import before it looked for one, so it never counted an imported scalar and reported "0 named scalar definition(s)" for a source number that the module imports as a named parameter, while typed numeric recall accepted the same import. The check now reads the parsed top-level `imports` list and counts only a direct scalar definition of the exact imported symbol in the resolved file. Text that only looks like an imports block (inside a block scalar or under another key), unparsable YAML, an item with whitespace or more than one `#`, an import of a symbol with a different value, a file-level import without a symbol, an unresolved or unsafe target, and a number with no parameter are still refused.
