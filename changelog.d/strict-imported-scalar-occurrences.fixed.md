Credit an explicitly imported parameter in the complete-source-unit numeric-occurrence check. The check dropped the `#symbol` suffix of each import before it looked for one, so it never counted an imported scalar and reported "0 named scalar definition(s)" for a source number that the module imports as a named parameter, while typed numeric recall accepted the same import. The check now reads the top-level `imports` list at the YAML node level, without merge-key or alias resolution, and counts only a direct scalar definition of the exact imported symbol in the resolved file. An item counts only as one whitespace-free `prefix:path#symbol` reference whose target the rules engine can load. Imports that only a merge key supplies, a file with a merge key, an alias, an explicit tag, a duplicate `imports` key or more than one document, text that only looks like an imports block, an unprefixed target, an import of a symbol with a different value, a file-level import without a symbol, an unresolved target, and a number with no parameter are still refused.
