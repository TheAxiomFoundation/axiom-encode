`axiom-encode ci` supports validate-rulespec pin 92ccb0f2, which rulespec-us calls since 4c9aeadd. It recognizes the caller's resolver that also reads `axiom_compose_ref`, runs the pre-check's ProgramSpec shape check with `guard-programs-root` (and checks that its interpreter has the pinned PyYAML), and reproduces the isolated dependency layout: checkouts under a dependency root outside the rules checkout, exported to repository pytest as `AXIOM_DEPENDENCY_ROOT`/`AXIOM_DEPENDENCY_STAGE`, with an empty staging directory left in the workspace and no `_axiom`, so the rules checkout's Cargo inputs no longer reach the engine build. When the caller pins a composer, ci checks the pin against `.axiom/workflow-toolchain.toml`, authenticates the `--compose-path` checkout, builds the composer runtime with uv and the encoder pin's own `provision_axiom_compose_runtime.py`, and passes it to the waiver audit (now `--json`), validation and companion tests, as CI does. New flag: `--compose-path`.
