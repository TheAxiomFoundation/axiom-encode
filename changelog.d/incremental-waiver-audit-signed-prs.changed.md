Make `validation-waivers audit --scope incremental` usable for signed encoder pull requests. A signed apply manifest at `.axiom/encoding-manifests/<module path>.json` is now classified as a change of its module instead of forcing the full audit; every other `.axiom` path, and a manifest whose module is absent, aliased or not a RuleSpec module, still forces it. The selector computes repository-wide inputs once and decides each waiver by a walk over a shared dependency graph, and each audit job selects within its own partition only, so the cost follows the partition. A waiver whose own read set cannot be classified is now audited by itself on every run instead of forcing the full audit for all waivers; a filesystem failure still audits every path given. Two guards no longer depend on the caller's changed-path list: an empty change set, and a head ledger that differs from the protected base ledger (records or bytes), each force the full audit. Full scope remains the default, and fingerprints and ledger transition checks are unchanged. See `docs/validation-waiver-audit-scope.md`.
