Add `axiom-encode manifest-audit`, which asserts that **every** committed encoding manifest matches the file it attests and that no file carries more than one live manifest. `guard-generated` asks whether a changed file has *a* matching attestation, so one good record satisfies it and any other record committed alongside goes unread; the audit asks the question an outside auditor would ask instead, over every manifest tree anywhere in the repo — including the `<jurisdiction>/.axiom/encoding-manifests/...` trees the guard does not enumerate, where 3,927 of rulespec-us's 5,235 records live. It is schema- and signature-agnostic (signature and schema validity stay with the guard) but fail-closed on shape: a blanked, empty, duplicate-keyed, or self-contradictory record, an empty or escaping path, a record or target that is a symlink or sits behind one, or a claim that would rebind across jurisdictions is a finding, not a skip. Superseded claims that cannot be pruned without destroying a still-true sibling attestation are retired in place via `.axiom/retired-manifest-claims.yaml`: an entry is a reviewed exception bound to one exact (manifest, path, sha256) claim, it verifies and authorizes nothing, an entry whose claim stops existing or that would retire a file's only true attestation fails the audit, and retiring a stale file's only attestation must be declared with `unattested: true` (axiom-encode#1282).
