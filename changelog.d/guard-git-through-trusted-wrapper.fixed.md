The encoder-identity and ancestry checks of `guard-generated` now work under the provisioned verification runtime. They called `git --no-replace-objects -c core.commitGraph=false -C …`, which the runtime's trusted git wrapper refuses because it accepts only `git -C <checkout> <command>`, so every manifest-bearing RuleSpec change failed with "encoder Git metadata is unavailable". The checks now call `git -C …` and take that hardening from their environment. The wrapper disables the commit graph and grafts itself, and admits exactly the read-only queries the checks make.
