Stop text that only looks like an imports block from excusing a validation finding. Nine checks let an import excuse a finding but took their import items from a line reader that matches `imports:` at any indent, so a block in a `summary: |` block scalar, under `module:` or in another text field suppressed the finding for a module that imports nothing: same-section subsection import missing, child fragment re-encoded, parent exception-list child import missing, cross-reference placeholder, encoded cross-reference placeholder, cross-reference numeric placeholder, cross-reference base mechanics omitted, embedded scalar literal, and the non-strict numeric-occurrence count. These checks, and the cross-statute definition, defined-term and canonical-concept import checks, now read the whitespace-free string items written in place under the one top-level `imports` key (`_engine_import_items`), the list the rules engine loads. A file that does not parse, that has more than one document, an alias, an explicit tag, a top-level merge key or a duplicate `imports` key, or whose `imports` value is not a sequence of strings earns no import credit in these checks. An item counts only when the line reader read it too, so no file passes a check that it failed before. A real top-level import in block form still excuses the finding. Checks where an extra import can only add a finding keep the line reader.
