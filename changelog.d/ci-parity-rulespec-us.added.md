`axiom-encode ci` supports validate-rulespec pins 0effa6a5 and 6f11be26, which rulespec-us uses, by executing the pinned workflow's own inline scripts from byte-exact packaged copies. It resolves dependency refs through a reviewed workflow-toolchain resolver and registry inputs from repository variables, and mirrors the shard matrix, partitioned waiver audits and the supervisor's empty child environment. Like a pull_request run, it validates GitHub's test merge when HEAD lacks the base, in a checkout named after the base repository, on a UTC clock and C.UTF-8 locale. It builds the pinned engine and binds only its debug binary, runs repository pytest in a venv provisioned with CI's install sequence and step environment, runs the shards job before dependency resolution (keeping its results when resolution fails), prints CI's selection headings for every leg, takes each leg's retired-schema skip list from its own run, stops companion-test groups at the first failure, uses CI's four waiver-audit workers, rejects case-aliased waiver paths, and verifies that both oracle classifiers import the pinned axiom-oracles. New flags: `--corpus-release-retired-public-key`, `--apply-public-key`, `--eval-public-key`, `--corpus-release-registry-url`, `--corpus-release-registry-anon-key`, `--pull-request`, `--github-repository`, `--base-branch` and `--jobs`. The engine is built from a fresh snapshot of the committed pin in a private target directory, as CI's fresh checkout is; the build verifies cargo's own artifact path, refuses Cargo config, manifests and toolchain overrides it cannot reproduce, requires rustup's default toolchain, and binds a copy of the built binary, and repository pytest runs with a fresh HOME and no global or system Git config; checkout links refuse a committed `_axiom` path.
