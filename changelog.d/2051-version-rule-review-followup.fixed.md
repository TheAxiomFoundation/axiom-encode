Close the follow-up findings of the axiom-encode#2051 review. The provisioner now refuses a head with a non-numeric version, as `version_provenance` and the `--apply` guard do, and, like them, takes the bump to the head's version as the latest bump. All three copies measure rule 2 from the commit at which `main` first reached the head's version, so a version that `main` leaves and declares again needs a bump. The `lint` version step refuses when the base or head does not name a commit, instead of passing it as a base without the bump workflow. The `--apply` guard reads the first-parent history under its own scrubbed git environment and turns a git failure there into its usual refusal, and every copy turns `log.showSignature` off. The bump workflow holds for a queued pull request only when its author is the App's Bot account, and its close loop lists up to 500 open pull requests instead of gh's default 30.
