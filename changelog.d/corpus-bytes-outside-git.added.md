Place a pinned corpus release's provisions in a corpus checkout that keeps its bytes outside git. When `LocalCorpusRelease` binds a checkout with `.axiom/corpus-locks/`, it verifies the signed release object and then places each missing provisions artifact, but only where the checkout's own scope lock pins that path to the release's sha256 and size. An artifact whose lock pins other bytes (a scope re-ingested after the release) is skipped and left as it is, and reading that scope fails with the reason, as it did before the switch. A file that differs from the release bytes its lock pins is left untouched and reported the same way. Each placed file comes from the first of these sources whose bytes hash to the release's sha256 and byte count: the `axiom-corpus-ingest` content cache, the file at the release's git commit, the lock file's `git_blob`, or the release's R2 bucket by sha256 key. Temporary files go to `data/corpus/.corpus-fetch-tmp/` with the `.corpus-fetch-` marker, never into a scope. Files are placed with `link(2)` or a no-replace rename; an existing file is never replaced, and no symlink is followed. Checkouts without lock files are unchanged. `axiom-encode corpus-fetch` does the same explicitly for provisions, inventory and coverage, and supervised CI reads from git objects through the trusted wrapper (docs/corpus-bytes-outside-git.md).
