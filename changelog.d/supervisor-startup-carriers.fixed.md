The signing supervisor now refuses more Python startup carriers in its trusted trees, including the ones CPython's path configuration reads under the supervisor's own `-I -S` start, before the trusted bootstrap runs. Names match in any case, on files and directories alike: `._pth` and `pybuilddir.txt` join `pyvenv.cfg`, `.pth`, `.egg-link` and `__editable__*`, and every `sitecustomize`/`usercustomize` form (package directory, `.pyc`, extension module) joins the `.py` one. Positional rules join them: a `python3*.zip` entry, file or directory, in `lib/` or `lib64/` of the interpreter's directory or of any ancestor of it, up to `/` (the stdlib zip slot `sys.path` lists first, which path configuration also looks for above the runtime root); the interpreter must sit directly in the runtime's `bin/`; and `bin/` may hold only regular files (`bin/lib`, `bin/Lib`, `bin/Modules` move the stdlib). `scripts/provision_verification_supervisor.py` purges the same forms case-insensitively, removes a stdlib zip that is a directory, keeps a `python3*.zip` data file outside `lib/`, and refuses an interpreter at the prefix root. Name and position rules cannot see a changed stdlib byte or an extension module beside a stdlib source; a pinned runtime-tree digest checked before exec would close that.
