Retire superseded apply manifests inside the live install transaction when `encode --apply` writes a new one. Re-generating a rule previously left its earlier manifest in place asserting a hash the file no longer had — on rulespec-us this had put 122 attestations out of date by late July and 303 by mid-August, because the guard reads only until it finds a match. The plan is computed against the live checkout (not the isolated signing stage, which holds no predecessor records), every record it touches is pinned to the digest of the bytes the plan was computed from so a concurrent change aborts the transaction, a record is deleted only when every claim it makes — deletion markers, unresolved and unsafe claims included — is covered by the new manifest, claims on surviving records are retired in place whether or not they are still true, and the post-install closure models the retirements. The apply transaction's canonical-target allowlist gains a delete-only allowance for manifests in the two dead layouts (checkout-root legacy and `<jurisdiction>/.axiom/...`) plus write access to the retired-claims file; writes to dead layouts stay forbidden (axiom-encode#1282).
