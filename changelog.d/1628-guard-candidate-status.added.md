Add `guard-generated --candidate-status`, a cheap JSON report that classifies a RuleSpec change set as an `unadmitted_reviewed_candidate` (exactly one canonical module plus its `.test.yaml` companion, no manifests, no other change), `admitted` (every changed module carries its manifest), `invalid` (with reasons such as several modules, a non-canonical path, a manifest-only change set, metadata or waiver changes), or `no_rulespec_change`. The report reads Git metadata and head blobs only (no corpus, engine, broker, or manifest verification), carries the citation, path, file sha256s and base/head SHAs for a later admission record, and leaves the guard's checks, issue output, and exit code unchanged (#1628, design step B3).
