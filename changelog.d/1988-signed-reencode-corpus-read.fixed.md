Signed targeted re-encodes now fetch R2-stored corpus scopes with the organization's read-only corpus credentials (`R2_CORPUS_READ_ACCESS_KEY_ID` and `R2_CORPUS_READ_SECRET_ACCESS_KEY`). Only the provision-fetch step holds any R2 credential. A check before the production-signing gate fails a run whose credentials are missing, so a signing review isn't wasted on a run that couldn't fetch its pinned corpus. The fetch step asks for the credentials only for a lock-pinned corpus; a lockless (git-history) pin reads its provisions from the checkout and needs none.
