Add `axiom-encode corpus-attestation-carry`, a dry run that lists, for each manifest in a RuleSpec repository, whether its `source_attestation` could carry to a newer signed corpus release: `current`, `carried`, `not-verifiable`, `unit-changed`, `unit-missing`, `context-changed`, `not-in-lineage`, `malformed` or `no-attestation`, with `resolution_checked` and `pair_gained_scopes`. It verifies the release objects' signatures, requires the attested files in the attested release, requires every provisions artifact of the unit's pairs and of the pairs of every corpus citation in the bound module files to be unchanged, and, with `--corpus-root`, re-resolves the unit and every cited path (same attestation apart from the release identity, same generation input, no amendment documents or request, cited rows in byte-identical artifacts). When the new release adds a scope to one of those pairs, re-resolution is required: without a corpus the verdict is `not-verifiable`. Nothing in validation calls it; the guard still requires an exact release match.
