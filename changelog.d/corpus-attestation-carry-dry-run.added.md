Add `axiom-encode corpus-attestation-carry`, a dry run that lists, for each signed encoding manifest in a RuleSpec repository, whether its `source_attestation` could carry to a newer signed corpus release: `current`, `carried`, `unit-changed`, `unit-missing`, `context-changed`, `not-in-lineage` or `malformed`. It verifies the release objects' signatures, requires the attested provisions files at their attested sha256 in the attested release, requires the unit's file and every provisions file of the unit's jurisdiction and document class to be unchanged in the new release (new scopes may be added), and, with `--corpus-root`, re-resolves each citation and requires the same attestation (except the three release identity fields), the same generation input and no amendment context. Nothing in validation calls it; the guard still requires an exact release match.
