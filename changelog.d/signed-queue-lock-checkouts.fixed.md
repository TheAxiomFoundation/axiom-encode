`scripts/prepare_signed_queue.py` now builds the protected SNAP queues from an axiom-corpus checkout that keeps its corpus bytes in lock files. In such a checkout it lists the Oregon and Utah manual directories from the checkout's scope locks as well as from disk. Before it hashes or reads a queue source, it puts the signed release's bytes in place with `axiom_encode.corpus_materialize`. A missing source comes from the cache, git history or R2, verified against the release's sha256 and byte count, and only where the checkout's own lock pins those bytes. A present source counts only if its lock pins the release's bytes. Any other source fails the build. Before, the Oregon and Utah build failed with "Oregon and Utah manual corpus records are required", and the all-state build failed on the first missing file. Checkouts without `.axiom/corpus-locks/` run the same code as before. New: `corpus_materialize.locked_directory_listing`.
