`scripts/prepare_signed_queue.py` now builds the protected SNAP queues from an axiom-corpus checkout that keeps its corpus bytes in lock files. In such a checkout it lists the Oregon and Utah manual directories from the checkout's scope locks as well as from disk, and before it hashes or reads a queue source it places the signed release's bytes with `axiom_encode.corpus_materialize`. Each source comes from the cache, git history or R2, verified against the release's sha256 and byte count, and only where the checkout's own lock pins those bytes. Any source that cannot be placed fails the build. Before, the Oregon and Utah build failed with "Oregon and Utah manual corpus records are required", and the all-state build failed on the first missing file. Checkouts without `.axiom/corpus-locks/` run the same code as before. New: `corpus_materialize.locked_directory_listing`.
