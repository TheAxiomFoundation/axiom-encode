The validator's strict companion-test reader now accepts a case whose explicit key overrides a key it merges in with `<<`, and loads the test exactly as `yaml.safe_load` does (#1943). It flattened merge keys before checking for duplicates, so a legal override read as a duplicate and the validator rejected companion tests that every other reader accepts. Two equal keys written in one mapping, including inside a merge source, are still rejected, and the error now names that key and its line rather than the override. Module loads are unchanged: the engine does not apply merge keys, so a module that overrides a merged key is still refused.
