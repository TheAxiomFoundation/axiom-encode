Recognize Federal Register (`<jurisdiction>/rulemaking/...`) corpus paths in the encode CLI. Such a target has no default RuleSpec path: without `--replace-rulespec-path`, `encode` refuses and tells the operator to pass the module's agency and subject path under `<jurisdiction>/policies/`, listing the modules under `<jurisdiction>/policies/` whose `source_verification.corpus_citation_path` is that document, and separately those that cite it in `corpus_citation_paths` or cite one of its pages, so a re-encode can land on the existing module; `--replace-rulespec-path` decides which of them it accepts. When the scan finds neither, the message says what it scanned rather than that no module exists. The eval run refuses the same targets, including the document's RuleSpec names `[<jurisdiction>:]policies|policy/rulemaking/...`. With an explicit path the run proceeds as for any other target. Statute, regulation and policy targets keep their default paths. The path adapters (eval output mapper, validator target normalization, CLI reverse mapping, dependency-stub classifier, source-completeness deferral roots and the corpus resolver's RuleSpec alias) agree on a `policies/rulemaking/` mapping for rulemaking sources and refuse a policy-class source inside that namespace, and `jurisdiction:root/...` or bare `root/...` import targets are no longer mistaken for corpus citations.
