`validation-waivers audit` can balance its matrix shards by measured cost. A repository may commit `.axiom/validation-waiver-audit-costs.json` (schema `axiom-encode/validation-waiver-audit-costs/v1`, integer milliseconds per module and, optionally, each shard's non-audit time), built from a past run's logs by the new `validation-waivers audit-costs` command, which warns when a log's timing lines do not match the module count in its audit plan line, or when a log has neither, as a failed download does. With the table, every shard assigns waiver paths longest first to the least-loaded key (LPT list scheduling from each key's baseline) and starts its own modules longest first; without one, ownership stays the legacy round-robin over the sorted ledger and partition reports keep their bytes. The table changes only which shard audits a path and when, never a fingerprint or verdict, and a table that exists but does not parse fails the audit. The audit also prints a plan line, a start line per module (a not-started line for one a broken worker pool refuses) and a heartbeat every 60 seconds that names each running module and its elapsed time, all on stderr, so a long module no longer leaves the log silent for over an hour.
