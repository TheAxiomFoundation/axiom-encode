RuleSpec modules and companion tests may now carry only the explicit YAML tags that PyYAML and the engine read alike (`!!map` or `!` on a mapping, `!!seq` or `!` on a sequence, `!!str` on a scalar), anywhere in the document. PyYAML loaded a `!!set` mapping as a set of its keys and an `!!omap` or `!!pairs` sequence as a list of tuples, while the engine ignored those tags and compiled the mapping or sequence, so a policy-bearing rule written `- !!set` passed strict proof validation and `proof_validation: !!set` turned strict mode off. Scalar tags such as `!!binary`, `!!null` and `! '0.1'` changed what PyYAML loaded, and `!!bool` or `!!timestamp` on other text made validation raise instead of reporting. Proof validation and the validator pipeline's preflight now report each such tag with its location; apply and the retry overlay refuse the file before any rewrite, and the eval repairs and materialization keep its raw text. A double-quoted escape beyond U+10FFFF or an impossible unquoted date, which make PyYAML raise a plain `ValueError` rather than a YAML error, is now reported as YAML that cannot be loaded at the apply preflight and stamping, the retry overlay, normalization, materialization and the eval repairs, instead of crashing them.
