RuleSpec modules may now use YAML merge keys (`<<`) only inside a rule's `metadata`. PyYAML applied merge keys while the engine reads `<<` as an ordinary key, so a rule or version written `- <<: *base` passed strict proof validation while the engine rejected it or compiled it without the merged fields, and apply stamping wrote the merged fields out, changing what the engine compiled. Proof validation and the validator pipeline's preflight now report each such merge key with its location; apply and the retry overlay refuse the module before any rewrite, and the eval repairs and normalization keep its raw text. Merges inside rule `metadata`, which `rulespec-uk` modules use for shared proof sources, and in companion tests are unchanged.
