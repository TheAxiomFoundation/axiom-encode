`uv.lock` now pins the build backends. A new `build` dependency group (hatchling, editables, poetry-core, cython, setuptools, wheel) locks them with hashes, and `[tool.uv] build-constraint-dependencies` gives `uv sync`, `uv lock` and `uv pip install` the same versions. Until now pyiceberg 0.10.0, pyroaring 1.0.3 on 3.14, the axiom-oracles git dependency and the project were built with whatever backend versions the index served. The verification staging in `bulk-encode`, `golden-regeneration` and `targeted-signed-reencode` passes the locked group's export to every `uv pip install --build-constraints`, and adds `--no-cache` because uv otherwise reuses a cached wheel whatever the constraints say. The reusable `signed-apply` workflow stages the encoder its `AXIOM_ENCODE_REF` pins, whose lock predates the group; a test requires the same constraints there once that pin moves. Every uv call in the four staging steps, the axiom-compose runtime and the selftest now passes `--no-config`. Without it, the runner's user `uv.toml` merges into the project settings, and a parent directory's config applies when the encoder's pyproject has no `[tool.uv]` (as at signed-apply's pinned ref); either could change what gets built. The axiom-compose runtime install adds `--no-build`: its export is wheels only, and the flag makes it fail rather than build. uv does not reject a build dependency that the export omits. A new `locked-builds` CI job (`scripts/check_locked_builds.py`) therefore builds every locked source with `uv build --require-hashes` on 3.13 and 3.14 and fails on any build dependency that is omitted or unhashed. The required `test (3.13)` check now passes only when that job does. The provisioner selftest now stages the pyyaml that `uv.lock` pins (the new `provision-selftest` group) with `--require-hashes` instead of the index's latest. Closes #1732.
