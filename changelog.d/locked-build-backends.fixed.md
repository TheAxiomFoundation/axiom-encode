`uv.lock` now pins the build backends. A new `build` dependency group (hatchling, editables, poetry-core, cython, setuptools, wheel) locks them with hashes, and `[tool.uv] build-constraint-dependencies` gives `uv sync`, `uv lock` and `uv pip install` the same versions. Until now uv built pyiceberg 0.10.0, pyroaring 1.0.3 on 3.14, the axiom-oracles git dependency and the project with whatever backend versions the index served. The verification staging in `bulk-encode`, `golden-regeneration` and `targeted-signed-reencode` passes the locked group's export to every `uv pip install --build-constraints`, and adds `--no-cache` because uv otherwise reuses a cached wheel whatever the constraints say. Every uv call in those three staging steps, the axiom-compose runtime install and the provisioner selftest now passes `--no-config`. Without it, the runner's user `uv.toml` merges into the project settings, and a parent directory's config applies to any project whose `pyproject.toml` has no `[tool.uv]` table; either could change what uv builds. The axiom-compose runtime install adds `--no-build`: its export holds only wheels, and the flag makes it fail rather than build. uv does not reject a build dependency that the constraints omit, so a new `locked-builds` CI job (`scripts/check_locked_builds.py`) builds every locked source with `uv build --require-hashes`, which fails when a build needs a dependency that the `build` group omits or leaves unhashed. It runs on 3.13, which these workflows use, and on 3.14, the default of the organization's reusable `validate-rulespec.yml`, which stages this lock too. The required `test (3.13)` check now fails unless both legs succeed, as it already did for the test shards and `real-engine`. `tests/test_verification_site_packages_lock.py` requires each staging install to read the constraints file its own step exports, and rejects any other write to that file (a redirect, an `exec` or bare redirection, a copy, a second assignment, an alias, or another group's export into it). `tests/test_workflow_toolchain_pins.py` allows `--build-constraints` only in that form. The lock test also rejects `--no-build-isolation` on any `--target` install, since uv then builds with whatever backends the environment already holds. The provisioner selftest now stages the pyyaml that `uv.lock` pins (the new `provision-selftest` group) with `--require-hashes` instead of the index's latest. Closes #1732.
