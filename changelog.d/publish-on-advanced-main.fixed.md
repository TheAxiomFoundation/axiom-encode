The targeted signed re-encode no longer fails with "rulespec ref is not the exact pull request base branch tip" when rulespec main moved only through repository plumbing. Both the start gate and the publish step now admit a main tip that advanced from the recorded base, if the base is a first-parent ancestor of that tip and every path main changed is one that the signed run never reads and that nothing signed binds: `.github/`, `tests/` (except the manifest and freeze metadata tests), `tools/`, `bulk/`, `.claude/`, root prose and licence files, and the two non-encode pins in `.axiom/workflow-toolchain.toml`. At publish, `prepare_signed_backfill.py advance-publication-base` replays the lane commits onto that tip by object identity. It then proves that the replay differs from the tip on exactly the lane paths and from the lane head on exactly the advance paths, records the proof in `publication-base.json`, and the PR must report the replayed base and head. Any other advance (toolchain, waivers, fingerprints, manifests, receipts, the reverse index, RuleSpec trees, `programs/`, encode-relevant pins) or any overlap with the lane still fails closed, and the error message keeps its old prefix.
