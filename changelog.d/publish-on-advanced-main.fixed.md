The targeted signed re-encode no longer fails with "rulespec ref is not the exact pull request base branch tip" when rulespec main moved only through repository plumbing. Both the start gate and the publish step now admit a main tip that advanced from the recorded base, if the base is a first-parent ancestor of that tip and every path main changed is plumbing that no signed manifest or the generated-provenance guard binds and that an ordinary apply lane never reads: `.github/`, `tests/` (except the manifest and freeze metadata tests), `tools/`, `bulk/`, `.claude/`, root prose and licence files, and the two non-encode pins in `.axiom/workflow-toolchain.toml`. At publish, `prepare_signed_backfill.py advance-publication-base` replays the lane commits onto that tip by object identity. It then proves, for each commit and for the final head, that the replay differs from the tip on exactly that commit's lane paths and from the original commit on exactly the advance paths. It records the proof in `publication-base.json`, and the PR must report the replayed base and head. The PR body carries only the advance path count and the evidence digest, never the main-controlled path names. The SNAP dispatch queue (`scripts/snap_dispatch_queue.py`) applies the same rule, `base_advance_binding_paths` plus first-parent ancestry from the GitHub compare API. It no longer cancels an unfinished run whose main moved only through plumbing. API or network errors, truncated comparisons and anything else unproven still count as stale. A completed run that failed at a base-checking step after main moved at all is still not counted, exactly as before. These cases keep the exact-tip demand and fail closed, and the error message keeps its old prefix:
- Receipt-bound lanes: legacy replacements and path migrations, whose reference inventories `git grep` the whole base tree, plumbing included, and are re-proved only at the recorded base. The start gate gets `--require-exact-tip` for legacy inputs.
- Lanes that delete a base path.
- Lanes that touch an advance path or a file/directory prefix of one.
- Any other advance (toolchain, waivers, fingerprints, manifests, receipts, the reverse index, RuleSpec trees, `programs/`, encode-relevant pins).
