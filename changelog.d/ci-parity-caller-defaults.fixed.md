`axiom-encode ci` type-checks caller inputs against the pinned workflow (YAML 1.2 booleans) and takes omitted inputs from its declared defaults; `validate-roots` defaulted to `auto` instead of `statutes regulations policies`. Gates now run against a fresh clone of the rules repository's committed HEAD, as `actions/checkout` produces, so uncommitted, ignored or index-hidden files, sparse patterns, local filters and hooks never reach them. The interpreter must be the caller's `python-version` and must not run optimized. Trust roots must be distinct across roles, as the supervisor requires. An installed or modified encoder, index flags that hide edits, or an unreadable `git status` can no longer pass as a pinned checkout. Ambient `GIT_*`, `PYTHON*` and `PYTEST_*` values no longer reach ci's git calls, embedded scripts or repository tests. The object mirror is fetched with an explicit User-Agent (r2.dev rejects urllib's default). ci no longer treats its own cached release object as a dirty corpus checkout, and it ignores `axiom-encode` mentions in workflow comments when checking gate coverage.
