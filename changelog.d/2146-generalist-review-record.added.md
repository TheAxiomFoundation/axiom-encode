Record the generalist review of each model-manifest unit in `encode --apply` and let a run require it (#2146). The encoder reports `passed`, `partial`, `failed`, `unavailable` or `skipped` in a `generalist_review` record. It records the reviewer backend and model when the encoder knows them, prompt and reviewed/applied byte and canonical-content digests when the encoder has them, and flags showing whether the reviewer saw each manifest file in full. For a scored verdict, the encoder records a finite score; otherwise, it leaves score, prompt and reviewed/applied digest fields null. The encoder binds the verdict only when the reviewed and applied canonical YAML digests match. It excludes the two `module.source_verification` stamp keys and ignores stamp-only verification mappings and empty module values. If the stamp's dump changes that digest, the encoder records `unavailable`; a dump-derived digest cannot supply an alternate binding. The signed model manifest carries the record when the target's protected base sets `encoder_verifier = "main"` with no `encoder_verifier_hold`. Every apply reads that setting, so a malformed one can block manifest writing without the flag. `encode --apply --require-review` requires a `passed` record, and the manifest writer checks again before signing. Both the CLI and direct apply entry point refuse exact-dependent legacy rewrites in required mode. Record-only mode can rewrite those dependents outside the record's model-manifest unit. The flag defaults to off.
