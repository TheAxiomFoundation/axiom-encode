Record the generalist review of every `encode --apply` and let a run require it (#2146). The encode outcome now carries a `generalist_review` record with a status (`passed`, `partial`, `failed`, `unavailable` or `skipped`), the reviewer CLI and model when known, the reviewer's verdict and score, the review prompt digest, the digests of the RuleSpec and companion test the reviewer read, and every applied file with whether it was reviewed and whether the review prompt showed it whole. `passed` means every applied file was reviewed in full; a pass on a candidate when another file is also applied, or when the prompt showed only the start of a file, is `partial`. A verdict counts only for the content that is applied, compared by a content digest that ignores the source stamp apply writes into `module.source_verification`: a review of a candidate that apply-time repairs changed afterwards is `unavailable`, and a reviewer that cannot start or whose output cannot be read is never `passed`. The signed apply manifest carries the same record for a target repository whose protected base verifies with the main encoder (`[workflow_toolchain] encoder_verifier = "main"` and no `encoder_verifier_hold`), because a verifier older than this change rejects the new field; manifests without it verify exactly as before. `encode --apply --require-review` refuses to apply unless the record is `passed`, ends the run with `apply_blocked_review` and a non-zero exit, and is enforced again by the manifest writer before it signs. The flag is the only switch and is off by default.
