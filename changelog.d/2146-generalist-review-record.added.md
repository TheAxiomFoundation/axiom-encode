Record the generalist review of each model-manifest unit in `encode --apply` and let a run require it (#2146). The encoder reports `passed`, `partial`, `failed`, `unavailable` or `skipped` in a `generalist_review` record. It records the reviewer backend and model when the encoder knows them, prompt and reviewed/applied byte and canonical-content digests when the encoder has them, and flags showing whether the reviewer saw each manifest file in full. For a scored verdict, the encoder records a finite score; otherwise, it leaves score, prompt and reviewed/applied digest fields null. The encoder binds the verdict only when the reviewed and applied canonical YAML digests match. It excludes the two `module.source_verification` stamp keys and ignores stamp-only verification mappings and empty module values. If the stamp's dump changes that digest, the encoder records `unavailable`; a dump-derived digest cannot supply an alternate binding. The signed model manifest carries the record when the target's protected base sets `encoder_verifier = "main"` with no `encoder_verifier_hold`. Every apply reads that setting, so a malformed one can block manifest writing without the flag. `encode --apply --require-review` requires a `passed` record, and the manifest writer checks again before signing. Both the CLI and direct apply entry point refuse exact-dependent legacy rewrites in required mode. Record-only mode can rewrite those dependents outside the record's model-manifest unit. The flag defaults to off. A `passed` or `partial` record needs the reviewer's own JSON boolean `passed: true`; a pass inferred from the score or from an empty `blocking_issues` list stays in eval scoring and yields `unavailable`. The shared reviewer parser refuses another spelling of the `passed` key (for example `Passed`) in any decoded object of the output. For a deferred module without a companion test, the generalist reviewer prompt shows the empty companion that apply writes, and a companion file the reviewer did not see is recorded as unreviewed (`partial`). Mapping keys that a YAML 1.1 or 1.2 reader gives equal values (`0x10` and `16`) leave a file without a content digest. The manifest writer reads the verifier mode and hold from one protected commit. The spelling rule also covers `score` and `blocking_issues` and quoted keys in objects that only a lenient reader accepts; a `score` that is not a JSON number is a parse failure for every reviewer. A companion test file that exists is always shown in the reviewer prompt, also when it is empty. A mapping key that is not a scalar, or that YAML 1.1 or YAML 1.2 core cannot construct, and keys that a mixed-dialect reader equates (`0o20` and `0b10000`), leave a file without a content digest. The record lists each applied file by manifest path and byte digest and binds the verdict to the reviewed module path and its companion test path only, so a file with equal bytes at another path, such as a repaired dependent companion test, stays not reviewed and makes the record `partial`. The canonical content digest also carries the type that `yaml.safe_load` gives each scalar, so a quoted and a plain spelling that the companion-test loader reads differently (`yes`, `0b10`, `2001-01-01`) are different content. For a companion test, an absent file, a null document (0 bytes, only comments, `~`), an empty mapping and an empty list are four contents, because the companion-test loader accepts only the list; a review of one does not cover another. A plain float that `yaml.safe_load` and a YAML 1.2 core reader read as one value is bound by that value, so the apply dump's respelling (`0.20` to `0.2`) keeps the review; quoted, tagged and integer scalars and `-0.0` keep their exact text.
