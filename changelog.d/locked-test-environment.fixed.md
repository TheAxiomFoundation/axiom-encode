CI now tests and lints against the `uv.lock` set. The `ci.yml` test job and the `signing-supervisor.yml` Python test environment previously ran `uv venv` plus `uv pip install -e ".[dev]"`, which ignores the lock and floats each `>=` dependency to the index's latest release; CI run 36166075448 ran the suite on sqlite-utils 4.2.1, cryptography 50.0.1 and supabase 2.31.0 against locked 3.39, 46.0.3 and 2.27.3. Both now run `uv sync --locked --python 3.13 --extra dev`, and the lint job runs the locked ruff instead of `uv tool install ruff`. Every action in `.github/workflows` is pinned to a full commit SHA, and every `astral-sh/setup-uv` step uses the same action commit and uv 0.11.7 (`ci.yml`, `signing-supervisor.yml` and `validate-snap-queue-activation.yml` had no uv version; `prepare-all-state-snap-queue.yml` ran setup-uv `e92bafb6`, which is v6.4.3 although its comment said v7.2.0, with uv 0.9.26). `tests/test_workflow_toolchain_pins.py` enforces these pins.
