Signed RuleSpec pull requests that add a citation no longer fail rulespec's `reverse-index` freshness check. Signed model applies never wrote `.axiom/index/provisions_to_rules.json`, so someone had to regenerate the index by hand on each PR. The publish step now runs `prepare_signed_backfill.py refresh-provisions-index`. It regenerates the index with `axiom_encode.provisions_index`, a byte-exact replica of the tree's own `tests/generate_reverse_index.py` (the generator's code is never executed in the protected job), and appends it as one clearly labelled unsigned commit that changes only that path. The refresh applies only when the tree tracks the index and its generator blob is a reproduced version. It skips lanes that already change the index (signed legacy post-images) or that carry legacy-replacement, path-migration or retired-source-metadata receipts. It also skips trees that the replica cannot reproduce: symlinked modules or roots, non-UTF-8 modules, and loader crashes. If the refresh fails, the signed lane is published unchanged, as before. The PR body reports the refresh mode, and the artifact carries `provisions-index.json`.
