Generated RuleSpec modules and companion tests with a duplicate mapping key anywhere, such as two root `rules` blocks or two `formula` keys in one rule version, are now rejected before apply rewrites them. Apply stamping, the apply and eval repairs, materialization and the retry overlay write these files back from a loaded payload, which kept only the last of two equal keys, so the first block was silently dropped while the engine compiled what was left. The diagnostic names the mapping path and both key positions, and the file is left unchanged.
