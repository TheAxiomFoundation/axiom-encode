Generated RuleSpec modules and companion tests with a duplicate mapping key anywhere, such as two root `rules` blocks or two `formula` keys in one rule version, are now rejected before apply rewrites them. Apply stamping, the apply and eval repairs, materialization and the retry overlay write these files back from a loaded payload, which kept only the last of two equal keys, so the first block was silently dropped while the engine compiled what was left. The diagnostic names the mapping path and both key positions, and the file is left unchanged. The check also compares a collection key that loads as a string, such as `? !!str {=: rules}`, does not crash on keys PyYAML cannot construct, and keeps a companion test raw when two of its keys collide only after the test normalizer strips thousands separators (`12,500` and `12500`).
