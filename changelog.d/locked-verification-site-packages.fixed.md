The protected verification supervisor's site-packages are now exactly the `uv.lock` set. `bulk-encode`, `golden-regeneration` and `targeted-signed-reencode` previously staged them with a resolving `uv pip install --target … ".[api]"`, which ignores the lock and pulls each `>=` dependency's latest release at run time. Targeted run 36174590343 staged `claude-agent-sdk==0.2.159` beside the locked `0.1.47`. Each workflow now exports the lock with `uv export --locked`, installs the hash-pinned registry set with `--require-hashes --no-deps`, installs the commit-pinned `axiom-oracles` git dependency and the project with `--no-deps`, and fails unless `uv pip freeze` of the staged tree equals the `uv sync --locked` environment. The axiom-compose runtime that `targeted-signed-reencode` stages from axiom-compose's lock now installs with `--require-hashes --no-deps` too. `tests/test_verification_site_packages_lock.py` finds every command with `tests/workflow_shell.py`, so `pip3`, `python -m pip`, `"$PYBIN" -m pip`, wrapped (`sudo`, `bash -c`, `eval`) and attached-option (`-tDIR`, `--target=DIR`) forms are covered. Outside the provisioner's selftest it rejects every pip install and uninstall (pip ignores the lock, and `PIP_TARGET` can aim it at a tree it never names), every `uv pip uninstall`, and any `--target` install that is not one of the locked forms. It rejects any command, assignment or redirection outside staging that names the verification tree or the axiom-compose runtime, other than that tree's locked install and its provisioner, and it counts each tree's name through the rest of the workflow's text, so a loop header, array, heredoc, wrapper option or YAML key such as `env:` that names a tree fails. It reads each provision's `--site-packages` with the provisioner's own argument parser, so a later duplicate or an abbreviation such as `--site-pack` cannot slip in an unlocked tree. It rejects a provision whose `if:` lets it run after a failed step, and a staging step with any key beyond `name`, `run` and `working-directory`. The issue233 diagnostic's job may run one locked `uv sync` and no other uv call or pip install, and only its provision may name that environment's purelib. It also runs each staging step against a fake `uv` to cover its fail-closed paths. `tests/workflow_shell.py` now records each command's redirections (a line that only redirects, such as `exec 3> "$f"`, is a command with no words) and the option values and positionals of each uv call, and both provisioners expose the argument parser their `main` uses.
