The protected verification supervisor's site-packages are now exactly the `uv.lock` set. `bulk-encode`, `golden-regeneration`, `targeted-signed-reencode`, and the reusable `signed-apply` workflow previously staged them with a resolving `pip install --target … ".[api]"` (or `.`), which ignores the lock and pulls each `>=` dependency's latest release at run time. Targeted run 36174590343 staged `claude-agent-sdk==0.2.159` beside the locked `0.1.47`. Each workflow now exports the lock with `uv export --locked`, installs the hash-pinned registry set with `--require-hashes --no-deps`, installs the commit-pinned `axiom-oracles` git dependency and the project with `--no-deps`, and fails unless `uv pip freeze` of the staged tree equals the `uv sync --locked` environment. The signed-apply job also drops its unlocked `pip install -e .` into the interpreter it provisions from. `tests/test_verification_site_packages_lock.py` rejects any unlocked `--target` install in a workflow and runs each staging step against a fake `uv` to cover its fail-closed paths.
