The raw interpretation YAML guard now runs on every RuleSpec document and closes five gaps. It rejects YAML merge keys that supply `module` or `module.interpretations`, and `!!merge` tags on those keys, since the engine does not apply merge keys and would read different interpretations from the encoder. It reports a duplicate root `module` key, where loading kept only the last block and apply stamping dropped the first. It rejects a `!!set` tag on the root or `module` mapping, which made PyYAML load the mapping as a set and skip validation while the engine still read it. It rejects UTF-16 surrogate code points in interpretation strings, which PyYAML decodes from escapes such as `"\uD800"` but the engine refuses, and diagnostics now escape any surrogate they echo. It also reads a `!!str` tag on the first key of an interpretation mapping as the key's tag, rather than rejecting it as a collection tag. Interpretation mapping keys must now be plain strings, so a merge key written as a tagged collection (`? !!merge [x]`) no longer hides what it merges from the check. Each refusal names its line and column. Text nested too deeply for the check to finish fails validation and is no longer rewritten by eval normalization or the retry overlay, and tags that make PyYAML raise while constructing a value fail validation with the raw issues instead of crashing.
