# Fix encode#1559 sol-review findings (Armenian editorial numeric recall)

Repo: TheAxiomFoundation/axiom-encode, worktree at this directory, branch `wt/encode-1559`,
tracks `origin/fix/editorial-numeric-recall` (PR #1559). Head at start: b2fd624d
("Align Armenian prompt with recall grammar", version 0.2.1752).

A sol exact-review of b2fd624d returned REQUEST CHANGES with three defects. Fix all three,
minimally and exactly:

## 1. HIGH — nested-parenthetical stripping
`source_completeness.py` strips an editorial-history candidate even when the candidate's
opening `(` is nested inside an outer parenthetical, e.g.

```
(անցումային պայման
(1-ին հոդվածը փոփ. 07.12.22 ՀՕ-538-Ն)
)
```

becomes `(անցումային պայման\n)`, wrongly suppressing numeric-recall pressure for `1` and `538`.
This contradicts the prompt contract at `src/axiom_encode/prompts/encoder.py:1174`.
Fix: track parenthesis depth; strip only candidates whose opening `(` is at depth zero.
Add exact-retention and end-to-end recall regression tests (nesting of a candidate inside an
outer parenthetical — existing coverage at tests/test_source_completeness.py:~23027 only covers
nesting inside the candidate).

## 2. MEDIUM — malformed token sequences pass the "fully validated" ledger grammar
`src/axiom_encode/harness/source_completeness.py:2207` accepts three-digit years via `\d{2,4}`,
and the token deletion at ~:11992 does not enforce separators on both sides of every token.
These are incorrectly stripped (must NOT be):

```
(1-ին հոդվածը փոփ. 07.12.222 ՀՕ-538-Ն)
(1-ին հոդվածը փոփ. 07.12.22 ՀՕ-538-Ն08.12.22 ՀՕ-539-Ն)
(1֊ին հոդվածը 07.12.22 ՀՕ֊538֊ՆԽՄԲ.)
```

Fix: use `\d{2}(?:\d{2})?` for years and full-match the history as a separator-delimited
sequence of action/citation tokens (or enforce allowed boundaries on both sides of both token
types). The third example also shows unbounded case-insensitive action matching when an
uppercase action is glued to a U+058A citation — bound it. Add negative `_analyze` regressions
for all three shapes.

## 3. MEDIUM — prompt permits semicolon separation the validator rejects
Prompt permits semicolons (`encoder.py:1172`) but the action boundary at
`source_completeness.py:2203` omits `;`, so `(1-ին հոդվածը փոփ; 07.12.22 ՀՕ-538-Ն)` stays in
recall text and a prompt-following encoder gets spurious numeric-recall failures.
Fix: include `;` in the action boundary as part of the complete token grammar. Add
prompt/validator parity + end-to-end recall coverage.
