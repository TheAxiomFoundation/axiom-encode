# Local subscription generation and central replacement signing

Status: **replacement signing is not implemented or activated by this document**.
The existing new-module precedent is rulespec-nz #133, admitted through encoder
#1910 and signed by protected run 38678166960. Do not use that precedent to
delete an existing manifest or bypass a replacement receipt.

## One-time setup

- Keep subscription login on the operator's trusted local machine. Never put
  personal `auth.json` in Git, Actions artifacts, logs, or public CI secrets.
- Use an operator-provisioned, pinned supervisor/Codex runtime as documented in
  `trusted-signing-supervisor.md`; local generation receives no apply key.
- Keep signing in the existing central protected environment. No local signing
  credential, separate notary rollout, or public-CI subscription login is needed
  for this separation.
- Before enabling replacements, review and implement a transaction that binds
  the exact base, every predecessor owner, every candidate pair, source inputs,
  generation/attempt evidence, and all affected dependents. Encoder #2008 adds
  exact new-candidate binding; it does not implement replacement signing.

## Per-encoding procedure

1. Select the signed source release and compatible encoder/engine/RuleSpec pins.
   Record the existing generation budget admission before local model execution;
   local generation must not reset or evade protected attempt budgets.
2. Generate and repair with supervised Codex against those inputs. Preserve
   complete generation evidence and use the real local outcome, not a declaration
   that the bytes were generated. Never manually edit RuleSpec or companions.
3. Freeze the exact candidate commit. Preserve historical ownership manifests.
   For a same-path replacement, prepare a read-only inventory:

   ```sh
   python -m axiom_encode.reviewed_replacement \
     --repo /absolute/path/to/rulespec-us \
     --base FULL_BASE_COMMIT --candidate FULL_CANDIDATE_COMMIT
   ```

   This prints JSON only. It reads committed objects, so dirty working-tree edits
   are excluded. It is **not** a successful encoding, validated ownership proof,
   admission record, or signing authorization. It currently refuses new modules,
   path migrations, manifest changes, and unrelated candidate changes. Unchanged
   companions are inventoried too. Source and dependent completeness remain
   mandatory separate checks; changed-file enumeration cannot prove them.
4. Independently review the exact generated primary/companion bytes, source
   fidelity, dependency closure, focused behavior and oracle cases. Regenerate
   on findings and review the new head. `not_comparable` is not parity.
5. Obtain reviewed admission for the exact candidate and predecessor transaction.
   **Replacement dispatch is unavailable until that contract and its verifier,
   receipt writer/readers, and workflow integration are reviewed and merged.**
6. The eventual central replacement operation must independently verify source
   and predecessor evidence, validate the full candidate transaction without
   rewriting generated bytes, sign truthful reviewed-candidate provenance, and
   atomically install replacement receipts/manifests. It must fail on stale pins,
   changed candidates, missing owners or budget evidence, and partial dependents.
7. Re-run program/oracle checks and exact-head CI; finish independent review before
   merge. Retire one-shot admission after merge. Each subsequent encoding repeats
   these gates; setup does not grant blanket approval to future files.

## Replacement transaction integration contract (proposed, not activated)

The current `_stage_signed_legacy_replacement_provenance` requires a signed
current-v5 **model apply** manifest. Do not weaken that predicate to accept any
signed JSON, or fabricate a model invocation from a reviewed candidate. The
existing `promote-reviewed-candidate` signs only validation of reviewed bytes.
These are different claims.

Implementation must cover the following together before activation:

| Boundary | Required behavior |
| --- | --- |
| Admission | Trusted reviewed record binds country, base and candidate commits, source release, all primary/companion hashes, predecessor identities, and generation/budget evidence. Caller declarations alone authorize nothing. |
| Predecessor | Resolve the historical owner from the admitted base using existing authenticated legacy-replacement checks; reject ambiguous owners, stale base, and unsupported v5 replacement classes. |
| Candidate | Read exact reviewed Git bytes and enforce the complete admitted file set. Verify generation evidence independently of the inventory. A Codex declaration cannot relabel OpenAI-produced files. |
| Validation | Reuse complete-source overlay and dependent validation on the full atomic transaction. Any validator rewrite means a new candidate/review, not silent mutation during signing. |
| Provenance | Introduce an explicitly reviewed replacement receipt form for candidate validation/promotion. Bind both candidate and predecessor; distinguish generator identity from central validator/signer identity. |
| Readers | Update protected manifest verification, legacy receipt authority, publication checks, and downstream pinned guards together. Preserve rejection of malformed and older unsupported forms. |
| Install | Reuse the journaled apply transaction with compare-before-install snapshots, post-install verification, and rollback. Install all dependent manifests and receipts atomically. |
| Dispatch | Only a reviewed exact admission on protected main can select this operation. Retain protected environment approvals and budget enforcement; do not treat inventory JSON as a workflow capability. |

Required integration tests include a valid synthetic legacy replacement and
dependent pair, modified candidate/companion, wrong owner and owner hash, wrong
source release, missing or mismatched budget evidence, unadmitted SHA, duplicate
owners, stale validation pins, omitted dependent, validator mutation, invalid
signature, partial install rollback, and downstream verification of the new
receipt. A test that only signs an isolated new module is insufficient.

This is a proposal for extending the established NZ handoff, not an assertion
that its existing authorization covers Arizona. Route confirmation is requested
on rulespec-us #2022, comment 6635900144. The read-only inventory can be reviewed
and tested before that decision; no production signer consumes it.
